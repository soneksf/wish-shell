# Етапи розроблення

Код розбитий на 8 етапів. Кожен етап — робоча програма, яка вміє трохи більше
за попередній. Проходити по черзі: підставити етап, зібрати, перевірити руками,
зрозуміти зміни, закомітити.

```bash
./use-stage.sh 1      # підставляє код етапу 1 у src/ і збирає
./wish                # перевірка руками
git add -A && git commit -m "..."
```

Побачити, що саме змінилося між етапами:
```bash
diff -u stages/04/src/shell.cpp stages/05/src/shell.cpp
```

| Етап | Що з'являється | Ключові виклики |
|---|---|---|
| 1 | Цикл читання, запрошення `wish> `, вихід по `exit` і EOF | `getline`, `fflush` |
| 2 | Запуск програми з `/bin` у дочірньому процесі | `fork`, `execv`, `waitpid` |
| 3 | Шлях пошуку і вбудована `path` | `access` |
| 4 | Вбудовані `cd` та `exit` з перевіркою аргументів | `chdir` |
| 5 | Перенаправлення `>` (stdout і stderr у файл) | `open`, `dup2` |
| 6 | Паралельні команди через `&` | кілька `fork` до першого `waitpid` |
| 7 | Пакетний режим і коди виходу | `fopen`, `exit(1)` |
| 8 | Офіційні тести OSTEP, CMake, документація | — |

Починаючи з етапу 7 повний набір тестів має проходити повністю:
```bash
make && ./test-wish.sh
```
На ранніх етапах частина тестів падає — це нормально, вони перевіряють функції,
яких ще немає.
